## 1. Pendahuluan

Dokumen ini memuat spesifikasi kebutuhan fungsional (Functional Requirements - FR) untuk sistem **Djaswita AR**. Sistem ini merupakan platform Augmented Reality berbasis marker dinamis yang dirancang untuk mendukung kegiatan promosi pariwisata PT Jaswita Jabar.

Kebutuhan fungsional dibagi secara terstruktur menjadi dua kategori utama: kebutuhan fungsional untuk aplikasi seluler berbasis Android (Unity Client) dan kebutuhan fungsional untuk Dashboard Admin berbasis web (Vite CMS).

> [!NOTE]
> Seluruh kebutuhan fungsional di bawah ini dirancang untuk dapat diimplementasikan oleh pengembang tunggal (solo developer) dengan memanfaatkan layanan backend-as-a-service Supabase.

## 2. Kebutuhan Fungsional Aplikasi AR Android (Unity Client)

Aplikasi seluler AR Android berfungsi sebagai perangkat interaktif yang digunakan pengunjung pameran untuk memindai penanda cetak (marker) dan melihat visualisasi digital pariwisata.

| ID Kebutuhan | Fungsi / Kebutuhan Fungsional | Deskripsi Detail Kebutuhan |
| :--- | :--- | :--- |
| **FR-MOB-01** | Deteksi Marker Real-time | Aplikasi harus dapat memindai dan mendeteksi gambar penanda fisik (image marker) yang terdaftar di database menggunakan Vuforia Engine SDK secara real-time via kamera perangkat Android. |
| **FR-MOB-02** | Proyeksi Konten Dinamis | Aplikasi harus dapat memproyeksikan konten multimedia secara dinamis berdasarkan konfigurasi target: model 3D (berformat GLB via glTFast), image carousel (slideshow gambar), atau video streaming (dari Google Drive via proxy). |
| **FR-MOB-03** | Auto-Scale & Auto-Placement | Aplikasi harus melakukan normalisasi skala secara otomatis (auto-scale) dan rotasi default sumbu Y dari model 3D berdasarkan bounding box-nya agar muat secara visual di layar tanpa terpotong (clipping). |
| **FR-MOB-04** | Manajemen Memori GPU (RAM) | Aplikasi harus membatasi tekstur memori GPU maksimal 12 marker/tekstur aktif sekaligus dengan metode pengosongan (eviction) untuk mencegah kebocoran RAM GPU. |
| **FR-MOB-05** | LRU Disk Caching | Aplikasi harus mengimplementasikan sistem caching penyimpanan disk lokal (kapasitas 500 MB) dengan algoritme Least Recently Used (LRU) untuk menyimpan model 3D agar tidak diunduh berulang. |
| **FR-MOB-06** | Deteksi Jaringan & Offline Fallback | Aplikasi harus mendeteksi ketersediaan internet. Jika offline, aplikasi menampilkan overlay notifikasi dan secara otomatis beralih ke database SQLite lokal agar konten yang ter-cache tetap dapat dipindai. |
| **FR-MOB-07** | Offline Sync Queue | Setiap data scan yang dilakukan secara luring harus dimasukkan ke dalam antrean lokal SQLite (Sync Queue) dan otomatis dikirimkan ke Supabase setelah koneksi internet kembali aktif. |
| **FR-MOB-08** | Jeda Pelacakan (Delayed Hide Logic) | Aplikasi harus menunda penyembunyian objek AR selama 0.5 detik saat kamera kehilangan pelacakan marker fisik (tracking loss) untuk menghindari flicker/kedipan visual sesaat. |

## 3. Kebutuhan Fungsional Dashboard CMS Web Admin

Dashboard CMS berbasis web digunakan oleh tim internal PT Jaswita Jabar untuk mengelola data target, melihat laporan statistik, mengkonfigurasi sistem, dan memantau audit log.

| ID Kebutuhan | Fungsi / Kebutuhan Fungsional | Deskripsi Detail Kebutuhan |
| :--- | :--- | :--- |
| **FR-ADM-01** | Autentikasi & Otorisasi RBAC | Menyediakan halaman login admin dengan token kedaluwarsa 12 jam, mendukung Role-Based Access Control: Superadmin (akses penuh), Admin (CRUD operasional), dan Member (view-only). |
| **FR-ADM-02** | Manajemen Target AR (CRUD) | Menyediakan form input untuk membuat, membaca, memperbarui, dan menghapus target AR, mengunggah marker ke Supabase Storage, serta menyimpan konfigurasi konten AR. |
| **FR-ADM-03** | Analisis Kualitas Marker | Mengintegrasikan algoritme Harris Corner Detector secara real-time pada browser saat admin memilih gambar marker, menilai kerapatan sudut fitur kontras, dan memberi rating kelayakan 1-5 bintang. |
| **FR-ADM-04** | Visualisasi Grafik Real-time | Menampilkan dashboard berisi visualisasi grafik (line chart, bar chart) performa pemindaian mingguan yang diperbarui secara langsung melalui WebSockets Supabase Realtime. |
| **FR-ADM-05** | Double Authentication PIN | Melindungi konfigurasi parameter sistem sensitif (seperti proxy Google Drive API key) dengan verifikasi PIN / kata sandi kedua bagi Superadmin. |
| **FR-ADM-06** | Pencatatan Log Audit (Audit Trail) | Mencatat setiap perubahan konfigurasi sensitif (siapa, aksi apa, kapan) ke tabel `app_settings_logs` secara otomatis. |
| **FR-ADM-07** | Monitoring Heartbeat Database | Memantau dan menampilkan indikator status koneksi (keaktifan) basis data Supabase secara berkala pada halaman pengaturan. |
| **FR-ADM-08** | Paginasi Audit Logs | Menyediakan navigasi halaman (paginasi) pada tabel log audit untuk mempercepat performa pemuatan data log berukuran besar. |
| **FR-ADM-09** | Optimasi Debounce Request | Mengimplementasikan debounce (tunda 500ms) pada form pencarian dan filter data untuk membatasi kuota request API ke database Supabase. |
